## Overview

v1.0 MVP delivers a single-owner, password-gated internal tool for logging observed BTC/ETH price divergence events, reviewing them against real historical candlestick data, and running an independent leverage/position-size calculator.

**Core Value Proposition**: Enable traders to quickly record, review, and analyze BTC ↔ ETH price divergence events, accumulating reliable historical observation data for strategic analysis.

**Live URL**: https://btcethdivergence.bryanlab.cc

**Deliverables**:
- Cursor-paginated Binance ingestion (1000 candles per call)

## Architectural Decisions

1. **Single Worker + Static Assets** (not Pages + Workers split)
   - Rationale: Simpler deployment, fewer mental models, easier debugging
   - Confirmed via architecture research Phase 1

2. **Cursor-based pagination** for Binance backfill
   - Rationale: Handles rate limits without re-querying, easy resumption
   - Enables daily cron without gap-checking logic

3. **Client-side calculator** (no backend)
   - Rationale: Reduces server load, works offline, fast feedback
   - Trade-off: No server-side validation (acceptable for self-service tool)

4. **Dual-layer authentication**
   - Layer 1: Cloudflare Access (zero-trust, Email OTP for UI, Service Token for cron)
   - Layer 2: INGEST_TOKEN (application-level security layer)
   - Rationale: Defense-in-depth, separates platform security (CF) from app security (token)

5. **Lightweight Charts v5** (not TradingView, not custom canvas)
   - Rationale: Battle-tested, minimal dependencies, works on CDN
   - Verified: Re-entrancy guard pattern works reliably

## Lessons Learned

### 1. Spike Tests First
Running the Binance reachability spike test before any backfill logic validated the entire approach. Would have blocked the project if Binance was geo-restricted.

### 2. Cursor-Based Pagination Simplifies Operations
Storing the cursor in the database eliminated the need for gap-checking logic in daily cron. Re-running backfill is idempotent.

### 3. Dual-Layer Auth Requires Careful Header Handling
Case-sensitive header names (CF-Access-Client-Id, not Cf-Access-Client-Id) caused initial confusion. Verified against official Cloudflare docs.

### 4. CORS Credentials: The Browser Surprise
Adding `credentials: 'include'` to fetch calls was the key unlock for browser-based authentication with Cloudflare Access. Curl worked without it; browsers did not.

### 5. Lightweight Charts v5 Re-entrancy Guard Works
The re-entrancy guard pattern (tracking pending updates) reliably prevents chart desync during rapid panning. No crashes observed across large date ranges.

### 6. TDD Workflow Invaluable for Authentication
When Phase 9 hit authentication bugs, switching to TDD (write test → observe failure → fix → pass test) provided systematic verification of each layer.
