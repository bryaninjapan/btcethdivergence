## Out of Scope

| Feature | Reason |
|---------|--------|
| Automated divergence detection | Defeats Core Value of manual judgment building |
| Overlay/ratio chart | OHLC detail lost; stacked side-by-side preferred |
| Click-to-populate from chart | Manual entry easier per owner |
| 4h+ timeframes | 1h sufficient; no aggregation needed |
| Additional pairs | BTC/ETH relationship is core |
| Multi-user | Single-owner private tool |
| Mobile app | Responsive web sufficient |
| Real-time streaming | Retrospective analysis; daily sync sufficient |
| Alerts/notifications | Requires automated detection |
| P&L / portfolio | Logs divergence, not trades |
| Exchange API | No API keys; manual entry sufficient |
| Chart tools | Lightweight Charts limitation; TradingView for that |

### Requirements Changed During v1 Development

### Deferred Items (v2+)
- Pagination (RecordsRepository supports it; deferred for single-owner scale)
- Per-route telemetry sampling (100% head sampling v1; granular sampling v2+)
- Advanced error logging (basic structure v1; advanced tracing v2+)

### Lessons Learned
1. **Frontend-first architecture** enables rapid iteration without backend slowdown
2. **Service layer pattern** pays dividends in testability and reusability (Phase 12)
3. **Single source of truth** (TemporalConverter, DIVERGENCE_TYPES) prevents subtle bugs
4. **No-build frontend** (Lightweight Charts CDN, plain JS) keeps deployment friction minimal
