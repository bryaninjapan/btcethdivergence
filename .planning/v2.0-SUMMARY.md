# v2.0 Milestone Summary: Architecture Deepening

**Status**: 🚀 PLANNING  
**Started**: 2026-09-02  
**Target Completion**: 1-1.5 weeks (4 phases, ~7-9 days work)  
**Phase Count**: 4 (Phase 14-17)

---

## What This Milestone Does

Systematically improves code quality, testability, and maintainability after v1.0 shipped. Consolidates scattered logic into deep, reusable modules following clean architecture principles:

| Focus Area | Problem | Solution | Phase |
|-----------|---------|----------|-------|
| Time Domain | Scattered `Math.floor(ms/1000)` across 8+ modules | Centralized `TemporalConverter` class | 14 |
| Divergence Types | Duplicated type definitions (validate.ts + records.js) | Unified source in `src/domains/divergence.ts` | 14 |
| Chart State | 4 separate chart modules (state, range, sync, charts) | Single `ChartManager` state machine | 15 |
| Records Service | Query logic scattered in route handlers | Rich `RecordsRepository` interface | 16 |
| Calculator | No server-side validation schema | Schema-driven validation module (prep) | 17 |

---

## Phase Breakdown

### Phase 14: Architecture Foundations (2 days)
**Theme**: Consolidate & Unify

- Create `TemporalConverter` for all time operations
- Unify divergence type definitions (backend + frontend)
- Migrate 8+ backend modules to use TemporalConverter
- 30+ unit tests

**Outcome**: Single source of truth for temporal logic; no scattered `Math.floor(ms/1000)`

---

### Phase 15: Frontend State Refactoring (2-3 days)
**Theme**: Merge & Simplify

- Merge 4 chart modules into unified `ChartManager` state machine
- Refactor `charts.js` to thin UI layer (≤5 direct Lightweight Charts calls)
- Remove: chart-state.js, chart-range.js, chart-sync.js
- 40+ unit + integration tests

**Outcome**: Testable, maintainable chart state with strong re-entrancy guarantees

---

### Phase 16: Backend Service Deepening (2 days)
**Theme**: Elevate & Enrich

- Extract query logic from route handlers into `RecordsRepository`
- Implement advanced queries: `listWithStats()`, `findByTimeRange()`, `findByType()`
- Simplify routes to ≤10 lines per endpoint
- 25+ unit tests (Mock D1), integration tests

**Outcome**: Thin, focused route handlers; rich, testable repository layer

---

### Phase 17: Future-Proofing (0.5 days, Optional)
**Theme**: Prepare & Extend

- Extract calculator validation rules into Zod schemas
- Create API endpoint stubs (`/api/calculator/validate`, `/api/calculator/compute`)
- No changes to client-side calculator
- 15+ unit tests

**Outcome**: Foundation ready for calculator API expansion (can implement later)

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|-----------|
| Refactoring breaks existing features | HIGH | Comprehensive test suite (365+ tests), E2E verification |
| Time conversions inconsistent | MEDIUM | TemporalConverter unit tests (boundary cases), type safety |
| Chart sync race conditions | MEDIUM | Re-entrancy guards in Phase 15, stress tests |
| Database queries regress | MEDIUM | Mock D1 unit tests + integration tests for all routes |
