# Plan 01-03 — Binance Reachability Spike & Fallback Decision

## Objective

Resolve the single largest architectural unknown (research Pitfall 1): prove a fetch to Binance's public kline endpoint succeeds from a **deployed** Cloudflare Worker, and document the outcome plus the selected Phase 2 ingestion path (DATA-07 / SC5).

## Success Criteria Coverage

- **SC5** (deployed-Worker fetch to Binance succeeds, OR a documented fallback path is selected) → Task 2 (the spike) and Task 3 (the decision + documentation).
- **DATA-07** (Binance reachability validated via spike before backfill work) → Tasks 2 & 3.

## Dependency Graph

- Task 1 (binance client) → Task 2 (deployed spike endpoint) → Task 3 (decision + SPIKE-REPORT.md, user checkpoint). Builds on the deployed Hono router from plan 01-02.

## Tasks

<task type="auto">
  <name>Implement the typed Binance kline client</name>
  <files>src/types.ts, src/lib/binance.ts, src/lib/binance.test.ts</files>
  <action>
    src/types.ts: add `BinanceKlineTuple` — a readonly tuple type capturing Binance's untyped array response (`[openTime, open, high, low, close, volume, ...]`), the six fields this project uses (the research flags a misindexed field here as the single highest-leverage type to get right).
    src/lib/binance.ts:
    - `parseKline(raw: BinanceKlineTuple): Kline` mapping indices 0..5 → open_time (divide ms by 1000 to seconds via `Math.floor(raw[0] / 1000)`), then **apply `Number()` or `parseFloat()` to indices 1–5** (open, high, low, close, volume) to coerce Binance's string-typed numbers to actual numbers before writing to D1. Research flags string-number mishandling as the highest-leverage data-correctness risk (PITFALLS.md Lesson 5).
    - `fetchKlines(host: string, symbol: string, startTime: number, limit = 1000)` → GET `${host}/api/v3/klines?symbol=${symbol}&interval=1h&limit=${limit}&startTime=${startTime}`. On non-2xx, throw a typed `BinanceError` carrying `status`; special-case 429 (`Retry-After` noted in message) and 418 (must NOT auto-retry — immediate backoff). On success read `X-MBX-USED-WEIGHT-1M` and return `{ klines: Kline[], weight: string | null }`.
    src/lib/binance.test.ts: a vitest test asserting `parseKline` maps a representative Binance array (including ms timestamps like `1705334400000` and string-typed numbers like `"29500.50"`) to the correct `Kline` with `open_time` in seconds, and **verifies all numeric fields are actual numbers** (e.g., `typeof parsed.open === 'number'`) with exact value equality checks proving coercion happened (not string-in-number-field). Also test that `fetchKlines` surfaces a 429 as a `BinanceError` with status 429 (mock `fetch` via `vi.stubGlobal`).
  </action>
  <verify>
    `npm run typecheck` exits 0.
    `npx vitest run src/lib/binance.test.ts` is green (parse mapping + 429 classification).
  </verify>
  <done>Typed client compiles, the parse test passes, and fetchKlines can target either Binance host with weight/429/418 awareness.</done>
</task>
