# Plan 07-02 — Record → Chart Deep Link: 查看K線 on a record row loads both charts centered on the record's window with 24h padding (CHART-06)

## Objective

Close the loop between the log and the chart. Task 1 adds the `查看K線` button to every record row in `public/js/records.js` and, on click, navigates to `/charts.html?start=…&end=…` built from `recordToRange(record)` — the ±24h-padded millisecond window already defined and unit-tested in plan 07-01. charts.js (07-01 Task 3) then picks those params up on load, so both charts render centered on the record's time range. Task 2 is the end-to-end proof of SC3: deploy, marker checks, the full vitest suite, and the browser checkpoint sequence (button visible → click → both charts load the padded window → pickers/summary reflect it → sync holds → no-params and malformed-params fallbacks still work), fixing any failure in the responsible file and re-deploying.

**Explicit non-goal:** ECHART-01/ECHART-02 (markers/highlights drawn ON the chart for the record's range) are v2 requirements and out of scope for Phase 7 — SC3 only requires the chart window to be loaded and centered, not visual annotations.

## Success Criteria Coverage

- **SC3** (clicking "View Chart" on a record row loads both charts centered on that record's time range with roughly 24h padding before and after) → Task 1 (`查看K線` button + `recordToRange`-built navigation) + Task 2 (E2E browser proof of padding + centering on both charts). The padding math itself is covered by 07-01 Task 1 (recordToRange ±24h + round-trip test).
- **CHART-06** maps to SC3.

## Dependency Graph

- Task 1 (records.js button + navigation, deploy) → Task 2 (E2E verification + fix loop). Plan 07-02 depends on 07-01 (Task 1's `recordToRange` and Task 3's param-driven init in charts.js). Acyclic.
