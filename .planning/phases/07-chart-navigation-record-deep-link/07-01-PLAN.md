# Plan 07-01 — Chart Navigation Controls: UTC custom range pickers + log-scale toggle for both charts (CHART-04, CHART-05)

## Objective

Give the owner control over *what* the two Phase 6 charts show and *how* they scale. Task 1 adds `public/js/chart-range.js` — a pure, unit-tested module holding the range math (default 30-day window, deep-link param parsing, record→range with ±24h padding) so all range logic is provable outside the browser. Task 2 adds a controls bar to `public/charts.html` (log-scale checkbox, UTC-labeled start/end dropdown pickers reusing the Phase 5 pattern, a `載入範圍` button, and a live range summary) plus its CSS. Task 3 rewires `public/js/charts.js` around a reusable `loadRange(startMs, endMs)` that sets data on the existing chart instances, re-aligns the synced logical range, applies the log-scale toggle to both charts at once, and initializes from URL params when present (the deep-link consumption half of CHART-06) or the default window otherwise.

**Explicit non-goals (Phase 7 scope, not built here):** the record-row `查看K線` button and its navigation (CHART-06 → plan 07-02 Task 1), and the end-to-end deep-link browser proof (07-02 Task 2). `recordToRange` is defined and tested here because 07-02 consumes it; the click surface that calls it ships in 07-02.

    ```
    export const PADDING_SECONDS = 24 * 3600;
    export const DEFAULT_WINDOW_SECONDS = 30 * 24 * 3600;

    export function recordToRange(record) {
      const startMs = (record.start_time - PADDING_SECONDS) * 1000;
      const endMs = (record.end_time + PADDING_SECONDS) * 1000;
      return { startMs, endMs };
    }

    export function parseRangeParams(search) {
      const params = new URLSearchParams(search);
      if (params.get('start') === null || params.get('end') === null) return null;
      const start = Number(params.get('start'));
      const end = Number(params.get('end'));
      if (!Number.isFinite(start) || !Number.isFinite(end)) return null;
      if (start >= end) return null;
      return { startMs: start, endMs: end };
    }

    export function nowRange() {
      const endMs = Date.now();
      return { startMs: endMs - DEFAULT_WINDOW_SECONDS * 1000, endMs };
    }
    ```
    Key points:
    - `recordToRange` is the CHART-06 contract: record times are unix seconds, `/api/klines` wants millisecond `start`/`end`, and SC3 requires roughly 24h padding before and after → subtract/add `PADDING_SECONDS` before the ms conversion. Charts.js and records.js both consume this so the padding is defined exactly once and unit-tested.
    - `parseRangeParams` returns `null` for absent params (URLSearchParams `.get` → null → `Number(null) === 0`, and `0 >= 0` → null), non-numeric values (`Number('abc')` → NaN), and inverted ranges (`start >= end`). A `null` result means charts.js falls back to `nowRange()`. Extra params (e.g. `symbol=`) are ignored.
    - `nowRange()` reproduces the Phase 6 default (last 30 days), so the default-load behavior is unchanged and the constant moves here as the single source of truth.

    Create public/js/chart-range.test.ts (vitest; imports `./chart-range.js`). Cases:
    1. recordToRange padding math (SC3): `recordToRange({ start_time: 1704067200, end_time: 1704074400 })` → `{ startMs: 1703980800000, endMs: 1704160800000 }` — exactly `(start - 86400) * 1000` and `(end + 86400) * 1000` (24h before, 24h after).
    2. parseRangeParams valid: `parseRangeParams('?start=1703980800000&end=1704160800000')` → `{ startMs: 1703980800000, endMs: 1704160800000 }`.
    3. parseRangeParams empty string → `null`.
    4. parseRangeParams missing end param (`'?start=1703980800000'`) → `null`.
    5. parseRangeParams missing start param (`'?end=1704160800000'`) → `null`.
    6. parseRangeParams non-numeric (`'?start=abc&end=xyz'`) → `null`.
    7. parseRangeParams inverted (`'?start=10&end=5'`) → `null`.
