# Plan 05-01 — Records Filtering: Backend query params + Frontend filter bar (REC-05, REC-06)

## Objective

Make the records table filterable by divergence type and by partial tag match, exactly as the locked PLAN.md API contract specifies (`GET /api/records?type=&tag=`). Task 1 adds server-side filtering to `listRecords()` and the GET route with Zod boundary validation; Task 2 wires a type `<select>` and a tag search input above the table that re-fetch through the existing `api()` chokepoint. Filtering is server-side (not a client-side slice of an unbounded fetch) so the behavior stays correct as the record count grows and matches the documented contract; pagination stays out of scope per the Phase 4 L4 decision.

## Success Criteria Coverage

- **SC1** (filter the records table to show only one divergence type at a time) → Task 1 (backend `type = ?` filter + invalid-type 400) + Task 2 (`#type-filter` select re-fetching `?type=`).
- **SC2** (search/filter records by a partial tag match) → Task 1 (backend `tags LIKE '%…%'` partial match) + Task 2 (`#tag-filter` search input, debounced, re-fetching `?tag=`).

## Dependency Graph

- Task 1 (db + validate + route + tests, deploy) → Task 2 (filter bar UI, deploy, browser checkpoint). Builds on plan 04-02's table rendering and `loadRecords()`. Consumed by nothing else. Consumed-by note: plan 05-02 edits the same `public/index.html` + `public/js/records.js`, so it is ordered after this plan to avoid file conflicts. Acyclic.

    `export async function listRecords(db: D1Database, filters: { type?: string; tag?: string } = {}): Promise<DivergenceRecord[]>`:
    - Build the WHERE clause from bound parameters only (never string-interpolating user input):
      ```
      const conditions: string[] = [];
      const params: (string)[] = [];
      if (filters.type) { conditions.push('type = ?'); params.push(filters.type); }
      if (filters.tag) { conditions.push('tags LIKE ?'); params.push(`%${filters.tag}%`); }
      const where = conditions.length ? ` WHERE ${conditions.join(' AND ')}` : '';
      ```
    - Return `db.prepare(\`SELECT * FROM divergence_records${where} ORDER BY start_time DESC\`).bind(...params).all<DivergenceRecord>().then(r => r.results)`.
    - Keep the existing L4 note comment (unbounded is fine at single-owner scale; no LIMIT/OFFSET — pagination is out of scope).

    src/lib/validate.ts — add the query schema next to the other boundary schemas:
    ```
    export const listRecordsQuerySchema = z.object({
      type: z.enum(['time_lag', 'structural', 'opposite']).optional(),
      tag: z.string().trim().max(200).optional(),
    });
    export type ListRecordsQuery = z.infer<typeof listRecordsQuerySchema>;
    ```

    src/routes/records.ts — update the GET handler to validate the query at the boundary (INFRA-03) before any DB call:
    - Import `listRecordsQuerySchema` (in addition to the existing `createRecordSchema`, `updateRecordSchema`, `validationMessage`).
    - In the GET handler: `const parsed = listRecordsQuerySchema.safeParse(c.req.query()); if (!parsed.success) return jsonError(\`Validation failed: ${validationMessage(parsed.error)}\`, 400);` then `const rows = await listRecords(c.env.DB, parsed.data);` (replacing the current `listRecords(c.env.DB)` call).
    - The frontend never sends an empty `type` (it omits the param when the filter is 全部), so the strict enum rejection of a stray `?type=` is intentional and consistent with INFRA-03.

    3. `GET /api/records?type=structural&tag=btc` → 200; SQL includes both `'type = ?'` and `'tags LIKE ?'` joined by `' AND '`; params include `'structural'` and `'%btc%'`.

    - Rewrite `loadRecords()` to read the filter bar and build the query string through `URLSearchParams` (values are encoded by the API, never injected into SQL — the server binds them):
      ```
      async function loadRecords() {
        const params = new URLSearchParams();
        const type = document.querySelector('#type-filter').value;
        const tag = document.querySelector('#tag-filter').value.trim();
        if (type) params.set('type', type);
        if (tag) params.set('tag', tag);
        const qs = params.toString();
        const data = await api(qs ? `/api/records?${qs}` : '/api/records');
        recordsCache = data;
        renderTable(data);
      }
      ```
