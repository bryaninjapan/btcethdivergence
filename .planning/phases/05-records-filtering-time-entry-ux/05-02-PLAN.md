# Plan 05-02 — Time-Entry UX: UTC-labeled year/month/day/hour dropdown pickers (REC-07, REC-08)

## Objective

Replace the Phase 4 free-text ISO time inputs (`<input id="start_time">` / `id="end_time"`, placeholder `YYYY-MM-DDTHH:MM:SSZ`) with dropdown pickers — year (2021-2026), month, day (adjusted per month, leap-year aware), hour (00:00-23:00) — and explicitly label every time input and the table's time columns as UTC. This eliminates typos and timezone confusion per the phase goal. Task 1 builds a pure `datetime.js` helper module with vitest coverage; Task 2 restructures the form markup and wires the pickers into create/edit/save, then deploys and verifies.

**Expected behavior note**: the pickers are hour-granularity only (REC-07 specifies hour 00:00-23:00, no minute). Editing a record whose stored time has non-zero minutes/seconds snaps it to :00 on save — an inherent, accepted consequence of the locked dropdown design for a 1h-candle tool, not a defect.

## Success Criteria Coverage

- **SC3** (select start/end via year/month/day/hour dropdowns instead of typing free text) → Task 1 (option-generation helpers) + Task 2 (form restructure + `pickerEpoch` save path; free-text inputs removed).
- **SC4** (every time input on the page explicitly labeled UTC) → Task 2 (form labels `開始時間 (UTC)` / `結束時間 (UTC)`, UTC-labeled table headers, page-level `所有時間皆為 UTC` note).

## Dependency Graph

- Task 1 (pure datetime.js + tests) → Task 2 (form + records.js wiring + deploy + browser checkpoint). Task 2 depends on 05-01 having run first only because both plans edit `public/index.html` and `public/js/records.js` — sequential execution avoids file conflicts; no functional dependency on filtering. Acyclic.
