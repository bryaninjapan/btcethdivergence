# Plan 04-02 — Records UI: Table, Create/Edit Form, Delete Confirmation

## Objective

Build the owner-facing Records page that the phase's "UI hint: yes" requires. The backend CRUD contract exists from plans 01-02 and 04-01; this plan wires a static (no-build) page to it: a newest-first table (SC4), a create/edit form dialog that persists via POST/PUT and re-renders immediately (SC1, SC2), an inline display of the server's validation message (SC5), and a delete-with-confirmation dialog (SC3). Everything is plain HTML/CSS/JS under `public/` served by the Static Assets binding — matching the locked "no build step, Google-AI-Studio-friendly" constraint in PROJECT.md.

**Explicit Phase 5+ scope NOT implemented here** (phase-boundary guard): type/tag filters (REC-05/06), dropdown time pickers (REC-07), explicit UTC labels (REC-08), the per-row "View Chart" deep link (CHART-06 → Phase 7), and the shared nav bar (INFRA-06 → Phase 9). Time entry is interim free-text ISO-8601 UTC, replaced by dropdowns in Phase 5.

## Success Criteria Coverage

- **SC1** (create with start/end/type/notes/tags, appears in the list) → Task 2 (submitForm POST + re-render) built on Task 1's table.
- **SC2** (edit and see the update immediately) → Task 2 (openForm pre-fill + PUT + immediate re-render, no page reload).
- **SC3** (delete after a confirm dialog, disappears from the list) → Task 3 (delete dialog gate + DELETE + row removal), on top of plan 04-01's DELETE route.
- **SC4** (view all records in a table, newest-first) → Task 1 (renderTable from GET /api/records, which is ordered start_time DESC).
- **SC5** (start not before end rejected with a clear message) → Task 2 (client-side guard plus inline display of the server's "start_time must be before end_time" 400 message).

## Dependency Graph

- Task 1 (api.js + page shell + table render) → Task 2 (create/edit forms) → Task 3 (delete dialog). Builds on plans 01-02 (GET/POST/PUT + validation) and 04-01 (DELETE). Acyclic; nothing else consumes it.
