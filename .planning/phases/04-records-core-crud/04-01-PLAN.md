# Plan 04-01 — Backend Records CRUD Completion: Verify + Deploy + Commit Tests

## Objective

Verify and deploy the existing backend CRUD implementation, and commit the untracked test suite to lock the contract. Plan 01-02 delivered `GET /api/records` (newest-first, SC4 read path), `POST /api/records` (REC-01), `PUT /api/records/:id` (REC-02 partial update), and the Zod `start_time < end_time` refine (REC-09). Commit 8fb7ccc added `DELETE /api/records/:id` (REC-03) and the `deleteRecord()` repository function. The existing vitest suite (`src/routes/records.test.ts`, FakeD1 pattern matching `klines.test.ts`/`admin.test.ts`) already proves the whole CRUD contract — including the SC5 rejection and the delete 200/404 path — so this plan verifies that existing code, deploys it, and commits the test file to lock it in CI.

## Success Criteria Coverage

- **SC3** (delete after confirming a dialog, disappears from the list) — backend half: Task 1 verifies the existing `deleteRecord` + `DELETE` route and confirms a deleted row disappears from `GET /api/records`. The confirmation dialog and row removal in the UI are plan 04-02 Task 3.
- **SC5** (start not before end is rejected with a clear message) — Task 2 commits and verifies the existing 400 behavior (`"start_time must be before end_time"`, no D1 write) in automated tests; surfacing that message in the UI is plan 04-02 Task 2.
- **REC-03** (delete a record) → Task 1 (backend verify) + 04-02 Task 3 (UI dialog).
- **REC-09** (validate start_time < end_time before saving) → Task 2 (tests verify the existing plan 01-02 refine on both POST and PUT).

## Dependency Graph

- Task 1 (verify + deploy) → Task 2 (commit test suite). Verifies existing code from 01-02 and 8fb7ccc. Consumed by plan 04-02 (the Records UI calls `DELETE /api/records/:id` and expects the 201/400/404 contract to be live). Acyclic; nothing outside this chain is consumed.
