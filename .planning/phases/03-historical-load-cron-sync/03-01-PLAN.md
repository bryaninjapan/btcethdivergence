# Phase 3: Historical Load & Cron Sync — Plan

**Phase Goal**: The full 2021-present kline history is loaded once and then kept current automatically every day without manual action.

**Depends on**: Phase 2 (backfill engine, fetcher, admin routes)

**Success Criteria** (from ROADMAP.md):
1. Running the backfill to completion for both BTCUSDT and ETHUSDT results in a D1 dataset spanning 2021-01 to present with no unexplained gaps.
2. Re-running the backfill or cron sync over an already-loaded range does not create duplicate rows.
3. Every day, a scheduled cron run fetches only the klines newer than the last stored candle for both symbols, with no manual trigger required.

## Stage 1: Historical Backfill (2021-03-25 → Now)

**Goal**: Load 4+ years of BTCUSDT and ETHUSDT history into D1 in one-time crawl.

**Current State**:
- D1 holds 3000 BTCUSDT rows (2021-03-25 → 2021-06-01)
- ETHUSDT: 0 rows
- Backfill engine proven to work (Phase 2 verified ✅)

**Method**:
```bash
# Looped execution until "reached now"
WORKER_URL=https://btcethdivergence.gn01968711.workers.dev \
INGEST_TOKEN=$INGEST_TOKEN \
SYMBOL=BTCUSDT \
node_modules/.bin/tsx scripts/backfill-fetcher.mts

# Repeat above command until fetcher logs "reached now"
# Then run same for ETHUSDT (repeat until "reached now")

# Alternative (using npm bin):
# $(npm bin)/tsx scripts/backfill-fetcher.mts
```

**Key Behaviors**:
- Fetcher reads cursor from D1 `backfill_state` table (per-symbol)
- Each run fetches max 1000 candles (Binance API limit)
- Cursor advances on each success; idempotent on re-runs (INSERT OR IGNORE)
- "Reached now" = 0 candles returned = success exit (no POST)
- 429/418 backoff logic in place (Phase 2 decideBackoff module)

**Duration**: ~2-4 hours (depends on Binance rate limits)

**Verification**:
```bash
# After Stage 1 completion, verify SC1 (no unexplained gaps):
npx wrangler d1 execute btcethdivergence --remote --command \
  "SELECT symbol, COUNT(*) AS count, MIN(open_time) AS earliest, MAX(open_time) AS latest FROM klines GROUP BY symbol"

# Expected: BTCUSDT and ETHUSDT both present, spanning 2021-01 → current date

# Critical: Check for consecutive gaps (1h candlesticks should have no missing hours)
npx wrangler d1 execute btcethdivergence --remote --command \
  "SELECT symbol, COUNT(*) AS gap_count FROM (
     SELECT symbol, open_time, LAG(open_time) OVER (PARTITION BY symbol ORDER BY open_time) as prev_time
     FROM klines
     WHERE open_time - prev_time > 3600  -- gap > 1 hour
   ) GROUP BY symbol"

# Expected: gap_count = 0 for both symbols (no gaps > 1h)
```

## Stage 2: Daily Cron Sync (2026-09-01 onward)

**Goal**: Keep D1 in sync with latest Binance candles, running automatically every day at 2 AM UTC.

**Setup** (one-time):

### Step 1: Create config directory
```bash
mkdir -p ~/.config/btcethdivergence
chmod 700 ~/.config/btcethdivergence
```

### Step 2: Store INGEST_TOKEN securely
```bash
echo "YOUR_INGEST_TOKEN_HERE" > ~/.config/btcethdivergence/ingest-token
chmod 600 ~/.config/btcethdivergence/ingest-token
```

### Step 3: Create launchd plist

Save as `~/Library/LaunchAgents/com.btcethdivergence.backfill.plist`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>com.btcethdivergence.backfill</string>
  
  <key>ProgramArguments</key>
  <array>
    <string>/usr/bin/env</string>
    <string>bash</string>
    <string>-c</string>
    <string>
      cd /Users/bryan/Documents/btcethdivergence && \
      export WORKER_URL="https://btcethdivergence.gn01968711.workers.dev" && \
      export INGEST_TOKEN="$( cat ~/.config/btcethdivergence/ingest-token )" && \
      export SYMBOL="BTCUSDT" && \
      ./node_modules/.bin/tsx scripts/backfill-fetcher.mts >> ~/.config/btcethdivergence/backfill.log 2>&1
    </string>
  </array>
  
  <key>StartCalendarInterval</key>
  <dict>
    <key>Hour</key>
    <integer>2</integer>
    <key>Minute</key>
    <integer>0</integer>
  </dict>
  
  <key>StandardOutPath</key>
  <string>/Users/bryan/.config/btcethdivergence/backfill.stdout</string>
  
  <key>StandardErrorPath</key>
  <string>/Users/bryan/.config/btcethdivergence/backfill.stderr</string>
</dict>
</plist>
```

### Step 4: Load plist into launchd
```bash
launchctl load ~/Library/LaunchAgents/com.btcethdivergence.backfill.plist
```

### Step 5: Verify it's loaded

## Known Unknowns & Risks

### Rate Limit Behavior Over 4+ Years
**Risk**: Binance `X-MBX-USED-WEIGHT-1M` may spike during historical crawl, triggering 429 or weight-based IP ban.

**Mitigation**: 
- Fetcher logs weight after each call (Phase 2 feature)
- Backoff logic handles 429 with Retry-After (60s floor if missing)
- If repeated 429s occur, defer backfill to off-peak hours or split across multiple days

### Cursor Persistence During Crash
**Risk**: Machine crash mid-backfill leaves cursor in D1, but partial batch may not have posted.

**Mitigation**:
- Cursor only advances on successful ingest POST
- Re-run of fetcher reads cursor from D1 and resumes from next hour
- No data loss, just slow recovery

### launchd Survival Across Sleep/Wake
**Risk**: macOS sleep may suppress launchd job execution.

**Mitigation**:
- launchd *usually* survives sleep/wake cycles (observed behavior)
- Monitor logs for first week to confirm consistent runs
- If issues arise, can switch to `crontab` as fallback

### ETHUSDT Dual-Run Staggering
**Risk**: Running BTCUSDT and ETHUSDT at same time may exceed rate limits or CPU quota.

**Mitigation**:
- Current plan: Two separate launchd jobs at different times (2 AM and 6 PM UTC)
- If one job fails, other is unaffected
- Can adjust times based on first week's weight logs
